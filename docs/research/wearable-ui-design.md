# 手环 / 手表 UI 设计原则（Vela 版）——少即是多

> 面向小米 Vela 手环（小米手环 8 Pro / 9 Pro / 10 等）与手表。核心结论：
> **同一套 UI 直接照搬手机端 = 灾难；手环必须做减法，第一屏只回答 1 个问题。**
> 来源：小米 Vela 官方「多屏设计」、Apple watchOS HIG、Wear OS 设计原则、Garmin Connect IQ UX 指南、glanceable smartwatch 研究，见文末链接。

## 1. 手环的物理与场景约束

| 约束 | 数字 / 事实 | 设计含义 |
|---|---|---|
| 屏幕 | 1.0–1.75 英寸；Vela 手环 336×480（8 Pro/9 Pro）、192×490（手环 9 胶囊）、212×520（手环 10 胶囊） | 一屏信息量 ≈ 手机的 1/6~1/8 |
| 观看时长 | 抬腕 1–3 秒（多数研究 2s 内） | 首屏必须“扫一眼就懂”，禁止需要阅读的段落 |
| 操作 | 点按 + 上下/左右滑，单手拇指，触控目标小 | 一屏最多 1~2 个可点区域 |
| 屏幕材质 | OLED，纯黑不发光的像素不耗电 | 深色底 + 大面积留白是省电与审美的共同解 |
| 佩戴环境 | 户外强光 / 夜间暗光 / 运动中晃动 | 高对比、大字号、少颜色，避免细线/低对比灰字 |

## 2. 官方设备矩阵（Vela「多屏设计」原文数据）

| 设备 | 形状 | 尺寸 | 分辨率 | PPI | DPR | 长宽比 |
|---|---|---|---|---|---|---|
| 小米手环 8 Pro / 9 Pro | 矩形 | 1.74" | 336×480 | 336 | 2.1 | ≈0.7 |
| 小米手环 9 | 跑道型胶囊 | 1.62" | 192×490 | 325 | 2.0 | ≈0.39 |
| 小米手环 10 | 胶囊形 | 1.725" | 212×520 | 326 | 2.0 | ≈0.41 |
| Xiaomi Watch S1 Pro / H1 / S3 / S4 / REDMI Watch 5 | 圆/矩形 | 1.43–2.07" | 466–514 | 323–326 | 2.0 | 1 / 0.7 |

官方建议：
- 圆屏/矩形屏可复用一套设计，**胶囊屏单独一套**；
- 弧形边缘有**安全区**，正文与可点内容必须放在安全区内；
- 推荐分辨率：圆 466×466、矩形 336×480、胶囊 192×490。

## 3. 八条“手环 UI 少即是多”原则

1. **Glanceable（可扫视）**：第一屏 = 1 个主数据 + 1 个状态 + 1 句行动建议。2 秒读不完 = 失败。
2. **信息预算**：一屏最多 1 个 hero 数字（≥72px）+ 1 个状态图标 + ≤1 行辅助文字；其余全部下移或删除。
3. **垂直流式**：手环用单列上下滑（vertical scroll/page），**不要**手机式三栏网格并排。
4. **字号地板**：主数据 ≥72–96px；次数据 ≥24px；辅助 ≥18px；**任何正文不低于 18px**（336×480 下 1px=1 物理像素）。
5. **对比优先**：主文字纯白/近白，强调色≤2 种；辅助灰不得低于 4.5:1 对比度；细线（1px）只用于分隔，不承载信息。
6. **单拇指触控**：可点区域 ≥40×40px，且靠近屏幕中下部；一屏 1~2 个。
7. **动效克制**：只做 150–250ms 的淡入/位移，用动效表达“层级变化”，不用装饰性动画（省电 + 不打断）。
8. **提醒优于展示**：手环的强项是“推送/震动提醒”，把紫外线过强、即将下雨、空气质量差做成一条大字提醒，比塞进界面更有效。

### 为什么是“少即是多”（理论依据）
- **认知负荷**：工作记忆有限（Miller 7±2；现代研究更接近 4±1），每多一个并排信息块都会增加扫视成本。
- **Hick 定律**：选项越多，决策时间越长；手环上可用时间只有 1–3 秒。
- **信噪比**：在极小屏幕上，次要信息不是“补充”，而是噪声；删掉 80% 才能让 20% 被看见。
- **Fitts 定律**：触控目标越小越远，点击越慢越易错；手环必须放大目标、减少目标。
- **OLED 省电**：纯黑像素不发光；少色、少亮、少动画直接延长续航。

## 4. 手环 vs 手机：设计差异对照

| 维度 | 手机 | 手环（正确做法） |
|---|---|---|
| 布局 | 网格/多卡片并排 | 单列垂直流，一行一个信息 |
| 信息量/屏 | 8–15 条 | 1 主 + 1 状态 + 1 建议 |
| 字号 | 12–17px 正文 | 正文 ≥18px，主数据 72–96px |
| 导航 | 多 tab / 面包屑 | 上滑分页（1–3 屏），或表盘/负一屏 |
| 图表 | 折线/柱状可读 | 用“趋势箭头 + 极简折线”代替坐标轴 |
| 长列表 | 可滚动浏览 | 横向分页，一屏一天/一小时 |
| 次要信息 | 卡片展示 | 删除或改为推送提醒 |

## 5. 对当前题 1 界面的审计（按手环标准）

| 元素 | 判定 | 处置 |
|---|---|---|
| 大温度 23° + 天气图标 + 多云 | ✅ 保留 | 第一屏 hero |
| “体感 22°” | ⚠️ 次要 | 第二屏或并入主数据副行 |
| 湿度 / 空气 / 紫外线 三卡并排 | ❌ 手环不可并排 | 改第二屏单列，仅保留“空气 良”色点 |
| 未来 5 小时 5 列 | ⚠️ 偏密 | 第二屏：趋势折线（现在→+5h） |
| 未来 7 天 7 列 | ❌ 不适合手环 | 删除或第三屏横滑“一天一屏” |
| 日出/日落 | ❌ 抬腕场景价值低 | 删除（或表盘组件） |
| 更新时间 14:20 | ❌ 噪声 | 删除 |
| 风向/风力 | ⚠️ 次要 | 第二屏一行，或删除 |
| 深色底 + 高对比 + 拟物图标 | ✅ 保留 | 继承设计语言 |
| “周六有雨，随身带伞” | ✅ 保留 | 提为第一屏行动建议，可联动震动提醒 |

**结论**：现有页面在 336×480 上是“把手机卡片压进手环”，信息过载、三栏不可读、7 天与日出日落属于噪声，需要按“极简重构”重做，而不是继续加横滑。

## 6. 重构方案（手环版）

### 屏幕 1：抬腕即看（默认）
```
┌──────────────────┐
│  北京 · 朝阳      │  18px 次文字
│                  │
│      23°         │  96px 主数据（hero）
│   ☁ 多云          │  图标 48 + 24px
│                  │
│  周六有雨，带伞 ☂ │  20px 行动建议（唯一强调色）
└──────────────────┘
```
- 只有 3 个信息：地点、温度+天气、行动建议。
- 底部 1 个上滑提示（细箭头，非文字）。

### 屏幕 2：上滑——趋势与体感
```
┌──────────────────┐
│ 未来 5 小时       │ 24px 标题
│   ╭──╮ 折线（无坐标轴，2 色以内）
│  23 → 19°        │
│ 体感 22° · 湿度 62%│ 22px 单行
│ 空气 良 ●         │ 色点 + 文字
└──────────────────┘
```

### 屏幕 3：再上滑——可选项（或删除）
- 只在“详细模式”展示：紫外线、风向、日出日落；
- 或直接砍掉，把“紫外线强/下雨”改成**震动 + 大字提醒**。

### 布局与尺寸规范（Vela 336×480）
- 安全边距：左右 24px、上 24px、下 20px（胶囊屏左右 16px + 安全区再收）；
- 主数据 96px / 行高 100；标题 24px / 行高 28；正文 ≥20px / 行高 24；
- 强调色 1 种（暖黄 #FBBF24），状态色 1 种（绿 #86EFAC / 红 #F87171），其余灰阶；
- 触控目标 ≥40×40；一屏 ≤2 个可点；
- 动效：屏幕切换淡入+上移 200ms；无循环动画（省电）。

## 7. 设计验收清单（可逐条打勾）

- [ ] 第一屏 2 秒内能读出“几度 + 天气 + 要不要带伞”；
- [ ] 第一屏元素 ≤3 个，字号 ≥20px，主数据 ≥72px；
- [ ] 没有任何三栏并排卡片；没有 7 天 7 列；
- [ ] 全部可点区域 ≥40×40，且一屏 ≤2 个；
- [ ] 纯黑/深色底，强调色 ≤2，辅助文字对比度 ≥4.5:1；
- [ ] 纵向滑动分页（1–3 屏），每屏只表达 1 个主题；
- [ ] 没有装饰性循环动画；动效只用于层级切换；
- [ ] 胶囊屏 + 矩形屏分别验证安全区不裁切；
- [ ] 删除的信息以“提醒/推送”方式补足（如带伞、紫外线）。
